# Drupal 7 → modern Drupal migration

Drupal 7 reached end of life on 2025-01-05. The path is a **migration into a fresh Drupal 10.6/11.x site**, not an upgrade of the D7 code. `migrate_drupal` (core) and `migrate_drupal_ui` provide the D7 source plugins and generated migrations; both were removed from core in 12.0.0-alpha1, so migrate on 10.6 or 11.x first and upgrade afterwards.

## Sequence
1. **Archaeology** (`drupal-legacy-archaeologist` agent for large sites): content types, fields (`field_config`/`field_config_instance`), vocabularies, users/roles, files, menus, custom modules with business rules (`hook_menu`, `hook_node_*`, cron, `variable_get` values), contrib modules and their D10/11 equivalents or replacements.
2. **Target site**: fresh install, required contrib for the target (Paragraphs, Media, Pathauto, Redirect, Metatag…), content model designed for the target (do not replicate D7 warts), config exported.
3. **Connection**: `$databases['migrate']['default']` in settings (read-only user), D7 files directory reachable (`source_base_path`).
4. **Generate**: `drush migrate:upgrade --legacy-db-key=migrate --legacy-root=/path/or/url --configure-only` (Migrate Upgrade module) → migrations as config; review `drush migrate:status`.
5. **Customize**: keep the generated structure migrations only if the target model matches; otherwise write content migrations by hand with `d7_node` sources and explicit process pipelines; map field renames with `migration_lookup`/`static_map`; files with `d7_file` + `file_copy`; images to Media via a follow-up migration; paragraphs from field collections (`d7_field_collection_item` via the Paragraphs module's migrations).
6. **Run** on LOCAL/DISPOSABLE with a copy of the D7 database; verify counts per type against D7 (`SELECT type, COUNT(*) FROM node WHERE status=1 GROUP BY type`), spot-check URLs (aliases via `d7_url_alias`), redirects for changed paths.
7. **Iterate** with `--update` for content freshness; final cut-over plan: content freeze, final incremental run, aliases/redirects, search reindex.

## Typical traps
| Trap | Handling |
|---|---|
| D7 `text` formats with PHP filter or custom filters | map formats explicitly (`d7_filter_format`), strip PHP |
| Body summaries, `field_collection`, `entityreference` | ERR/Paragraphs migrations, `sub_process` |
| Files outside `sites/default/files`, private files | `source_base_path`, private scheme mapping |
| Users with old password hashes | core D7 password hashing supported on login; roles mapped via `d7_user_role` |
| Menu links to removed paths | `d7_menu_links` + review; redirects |
| Custom D7 modules with data tables | custom source plugins (`SqlBase` on the `migrate` key) |
| Views, Rules, Panels | rebuilt by hand; no migration |
| i18n / entity_translation | `d7_node_translation` (i18n), `d7_node_entity_translation` / `d7_taxonomy_term_entity_translation` / `d7_user_entity_translation` (entity_translation); verify language codes |

## Verification
- `drush migrate:status` counts vs D7 counts per bundle; `migrate:messages` empty or explained.
- Kernel test with `MigrateDrupal7TestBase` and a D7 fixture dump (`core/modules/migrate_drupal/tests/fixtures/drupal7.php`) for custom process plugins.
- L3: browse migrated pages as anonymous and as an editor; check aliases, files, images, translations.
