# Security checklist (Drupal)

Each row: what to look for, how to find it, the Drupal-native fix. Grep patterns are starting points, not verdicts.

| Area | Look for | Find | Fix |
|---|---|---|---|
| Authentication | custom login/session handling, cookies, tokens in URLs, `user_pass_reset` misuse | `grep -rn "session\|cookie\|setcookie\|user_login_finalize"` | core `user.auth`, `basic_auth`/`simple_oauth`, `_user_is_logged_in`; never roll your own |
| Authorization / permissions | routes without requirements, `_access: 'TRUE'`, `administer site configuration` reused for everything, permission checks on the wrong account | `grep -rn "_access: 'TRUE'" **/*.routing.yml`; permissions.yml vs usage | `_permission` per capability, `restrict access: true` for admin, `AccessResult` with cacheability |
| Entity access | `->load(`, `->loadMultiple(`, `->getQuery()` without `accessCheck(TRUE)`, followed by output | `grep -rn "loadMultiple\|->load(\|getQuery()" src/` then check the consumer | `$entity->access('view')`, `accessCheck(TRUE)`, `_entity_access` on routes |
| Field access | rendering raw field values from other users' entities | `->get('field_x')->value` in controllers/blocks | `$entity->get('f')->access('view')` or view builders/formatters |
| CSRF | state-changing GET links, custom POST endpoints outside Form API, AJAX that mutates | routes with `methods: [POST]` without `_csrf_request_header_token`; links to `/x/delete/{id}` | Form API (confirm forms), `_csrf_token: 'TRUE'` on link routes, `_csrf_request_header_token` for JSON |
| XSS | `Markup::create(`, `|raw`, `#markup` with variables, `FormattableMarkup` with unsafe placeholders, `Xss::filterAdmin` on user input, `#allowed_tags`, `#children`, JS `innerHTML` with server data | `grep -rn "Markup::create\|FormattableMarkup\|filterAdmin\||raw\|innerHTML"` | `t()` with `@`/`%` placeholders, `#plain_text`, `Html::escape`, `{{ }}` autoescape, `drupalSettings` + text nodes |
| SQL injection | string concatenation in `db_query`/`->query(`, `->condition()` with raw operator from input, dynamic table names | `grep -rn "->query(\|db_query\|sql:query" ` | placeholders `:name`, query builder, `escapeTable`/`escapeField` |
| SSRF / external calls | `http_client` with user-controlled URLs, `file_get_contents($url)` | `grep -rn "http_client\|Guzzle\|file_get_contents(\$"` | allow-list hosts, `UrlHelper::isValid($url, TRUE)`, timeouts |
| Path traversal / files | user input in file paths, `file_get_contents`, `unlink`, uploads without validators, public files that should be private | `grep -rn "\.\./\|unlink(\|move_uploaded_file\|file_save_data"` | `#upload_validators` (`FileExtension`, `FileSizeLimit`), `private://` scheme, `FileSystemInterface` methods, stream wrappers |
| Command execution / deserialization | `exec`, `shell_exec`, `system`, `passthru`, `unserialize(` of external data, `eval(` | `grep -rnE "\b(exec|shell_exec|system|passthru|unserialize|eval)\("` | avoid; `Symfony\Component\Process` with fixed args; `json_decode` |
| Open redirects | `RedirectResponse` with request-provided URL, `?destination=` handling | `grep -rn "RedirectResponse\|->redirect(\|destination"` | `Url::fromUserInput`, `TrustedRedirectResponse` only for allow-listed hosts, `RedirectDestination` service |
| Information disclosure | verbose errors in production, stack traces in JSON, exposing IDs/emails/roles in APIs, `.env`/backups under docroot | settings `error_level`; controllers returning entities wholesale | error_level `hide` outside LOCAL; explicit response DTOs; serve files outside docroot |
| Secrets and logging | API keys in config/state/code, credentials in watchdog, request bodies logged | `grep -rn "api_key\|secret\|password" config/ src/` | settings.php from environment, Key module; log identifiers only |
| API / AJAX / REST | JSON endpoints with `_access: 'TRUE'`, REST resources without auth providers, JSON:API exposing private fields | routing.yml, `rest.resource.*` config, `jsonapi_extras` | permission per endpoint, `_format`, authentication providers, field access respected by JSON:API (verify config) |
| Cache leaks | personalized output without `user` context; permission-dependent without `user.permissions`; `max-age` on responses containing private data | see `drupal-cacheability` | contexts/tags/max-age; `Cache-Control: private` for authenticated JSON |
| Trusted callbacks | `#pre_render`/`#lazy_builder`/`#post_render` pointing to arbitrary functions | `grep -rn "#pre_render\|#lazy_builder\|#post_render"` | `TrustedCallbackInterface::trustedCallbacks()` on the class, service `:method` syntax |
| Dependencies | contrib with advisories, unsupported branches, patched security-relevant packages | `composer audit`, `drush pm:security`, `drush pm:security-php` | report; upgrade only when asked, with tests |

Classification per finding: `CONFIRMED` (path from input to sink shown), `PROBABLE`, `DEFENSE-IN-DEPTH`, `FALSE POSITIVE` (with reason). Severity: CRITICAL (unauthenticated data loss/RCE/account takeover), HIGH (auth bypass, stored/reflected XSS on privileged pages, cross-user data), MEDIUM (needs privileges or unusual config), LOW (hardening).
